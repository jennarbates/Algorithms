Floors and ceilings

Big-O only ever gives a ceiling, and a ceiling can be as loose as you like: 10 log n is O(log n), and also O(n), O(n²) and so on. To say how fast something really grows you need a floor as well.

Three definitions, one shape (c, c1, c2 > 0 and n0 ≥ 0 are numbers you choose)
ClaimMeansPicture
T(n) = O(f(n))T(n) ≤ c·f(n) for all n ≥ n0ceiling
T(n) = Ω(f(n))T(n) ≥ c·f(n) for all n ≥ n0floor
T(n) = Θ(f(n))c1·f(n) ≤ T(n) ≤ c2·f(n) for all n ≥ n0both: tight

Worked example: n − 10 = Ω(n) (the slide 8 clicker)

We need n − 10 ≥ cn. That rearranges to (1 − c)n ≥ 10, which is possible only if c < 1. With c = 0.5 it holds from n = 20; with c = 0.99 from n = 1000, where the two sides are exactly equal; with c = 2 or 20, never.

Worked example: 32n² + 17n + 1 = Θ(n²) (slide 11)

Floor: throw the positive terms away. 32n² + 17n + 1 ≥ 32n² at every n, so c1 = 32 from n = 0.

Ceiling: 33n² works once n² ≥ 17n + 1, first true at n = 18. Or round every term up: 32n² + 17n + 1 ≤ 32n² + 17n² + n² = 50n² for n ≥ 1.

One n0 for both: the later of the two. c1 = 32, c2 = 33, n0 = 18. It is not Θ(n): no c keeps c·n above 32n². And not Θ(n³): no c keeps c·n³ below it.

Moves that find witnesses. Ceiling: round every term up to the biggest shape. Floor: drop positive terms; for a negative term, give up part of the constant (n − 10 ≥ ½n once ½n ≥ 10). Then solve for n0, and check the first whole number.

Count every step

Asymptotic notation is about a count. Get the count first, exactly if you can, and read the bound off it.

Print1(n)
for i = 1 to n do
  print "X"
  for j = 1 to n do
    print "Y"

Each of the n rounds prints one X and n Y: n(1 + n) = n² + n characters. At n = 4: XYYYYXYYYYXYYYYXYYYY, 20 characters.

Print2(n)
for i = 1 to n do
  print "X"
  if i == 1 then
    for j = 1 to n do
      print "Y"

The Y loop runs only when i = 1: n + n = 2n characters. At n = 4: XYYYYXXX, 8 characters. Nested-looking, but linear.

Many bounds are true; one is tight

n² + n is Ω(√n), Θ(n²) and O(n⁴), all at once. Only Θ(n²) pins it down. 2n is Θ(n).

foo and bar (slides 4 and 12)

foo is two nested loops from 1 to n, bar is three. Both are O(n³), and yet they are not the same: foo is Θ(n²), bar Θ(n³). A ceiling alone cannot tell two algorithms apart.

The triangle

sum-product
sum = 0
for i = 1 to n do
  for j = i to n do
    sum += A[i]*A[j]

Each pair (i, j) the inner line runs on is one cell of an n × n grid, and it runs exactly on the cells with j ≥ i: a triangle, diagonal included.

n = 8. Shaded: every step that runs. Outlined: the easy way's square.

The hard way

Count all of it: n + (n − 1) + … + 1 = n(n + 1)/2. At n = 8: 36. At least n²/2, so Ω(n²).

The easy way

Ignore every step with i > n/2 or j < n/2. What is left is a square of ⌊n/2⌋ × (⌊n/2⌋ + 1) steps, all inside the triangle, so the program does at least that many. At n = 8: 20 ≥ (n/2)² = 16. A constant times n², so Ω(n²), without ever finding the exact count.

Checking the slide. "At least (n/2)²" holds for even n. For odd n the square has ⌊n/2⌋(⌊n/2⌋ + 1) steps, a quarter below (n/2)²: at n = 5, 6 against 6.25. The conclusion survives, since it is at least ((n − 1)/2)².

The general moves. Upper bounds: add work that is not there (every loop runs to n). Lower bounds: throw work away (keep a part you can count). Both give Θ(n²) here: 20 ≤ 36 ≤ 64.

Additivity, upgraded. If f and g are nonnegative and f = O(g), then f + g = Θ(g): the floor is free, since f + g ≥ g. So n² + 42n + n log n = Θ(n²).

Polynomial or not

An algorithm runs in polynomial time if its running time is O(nᵈ) for some constant d.

Why this is the definition of efficient (slide 17)

  • It matches practice: almost all practically efficient algorithms are polynomial.
  • It usually separates a clever algorithm from brute force. Stable matching by brute force tries n! matchings (3,628,800 at n = 10); propose-and-reject makes at most n² = 100 proposals.
  • It is refutable: it gives a way to say an algorithm is not efficient, or that no efficient algorithm exists.

Polynomial says nothing about the degree: n¹⁰⁰ is polynomial. And every exponential passes every polynomial eventually: 2ⁿ overtakes n¹⁰ between n = 58 and 59, and stays ahead.

Three loops deep

The triangle’s moves work one dimension up. The count is a sum of sums; the ceiling lets every loop run to n; the floor keeps a box of triples where every one really runs, and each side of the box is a constant fraction of n.

triangles(n)
for i = 1 to n do
  for j = i + 1 to n do
    for k = j + 1 to n do
      check points i, j, k

Exact: n(n − 1)(n − 2)/6. The bands are in order, low, middle, high, so every triple in the box has i < j < k, and the loops reach every such triple.

Box at n = 12: i ≤ n/3, n/3 < j ≤ 2n/3, k > 2n/3: 4 × 4 × 4 = 64 steps, of 220 in all.

deeper(n)
for i = 1 to n do
  for j = i to n do
    for k = 1 to j do
      do one step

Exact: n(n + 1)(2n + 1)/6. i ≤ n/2 ≤ j, so the pair is reached, as in the triangle; and k ≤ n/2 ≤ j, so k is inside its loop.

Box at n = 12: i ≤ n/2, j ≥ n/2, k ≤ n/2: 6 × 7 × 6 = 252 steps, of 650 in all.

Choosing a box. Pick a band for each index so that (1) every triple in the box satisfies the loop conditions, and (2) each band has at least a constant fraction of n values. Then the box has at least c·n³ steps, and the program at least that many: Ω(n³).
A box that is too thin proves too little. If one band has only 10 values, the box has about 10·n² steps: a true floor, but only Ω(n²).

Same answer, less work

powers, from scratch
for k = 1 to n do
  p = 1
  for t = 1 to k do
    p = p · x
  P[k] = p

n(n + 1)/2 multiplications: 55 at n = 10. Θ(n²).

powers, reusing the last one
p = 1
for k = 1 to n do
  p = p · x
  P[k] = p

n multiplications: 10 at n = 10. Θ(n).

Same table, entry for entry. The slow one rebuilt xᵏ⁻¹ inside every xᵏ; the fast one kept it. Strictly faster means the ratio goes to 0: here n / (n(n + 1)/2) = 2/(n + 1) → 0. A version that did half the work would be faster, but not strictly: the ratio would be ½.

The output is a floor. Whatever the algorithm, it must write its answer. The powers table has n entries, so Ω(n): the fast version is as good as it gets. A times table has n² entries (100 at n = 10), so no algorithm fills it in less than Ω(n²).

One-page summary

Definitions

  • O: T ≤ c·f from n0 on. A ceiling, and it can be loose.
  • Ω: T ≥ c·f from n0 on. A floor.
  • Θ: both, c1·f ≤ T ≤ c2·f, one n0 (the later one). Tight.
  • f = O(g) says nothing about whether g = O(f).

Finding witnesses

  • Ceiling: round every term up to the biggest shape.
  • Floor: drop positive terms; pay for negative ones with part of the constant.
  • Solve for n0, then check the first whole number (≥ allows equality).
  • For Ω, c must be below the leading coefficient; for O, above it (or equal, if the rest is ≤ 0).

Counting

  • Count exactly first; the bound comes from the count.
  • Add per round, don't multiply by nesting depth (Print2 is 2n).
  • Upper bound: add work that is not there. Lower bound: throw work away.
  • 1 + 2 + … + n = n(n + 1)/2 = Θ(n²).
  • If f = O(g) and both ≥ 0: f + g = Θ(g).

Polynomial time

  • O(nᵈ) for some constant d.
  • log < polynomial < exponential < factorial.
  • Brute force is often n! or 2ⁿ; the clever algorithm is polynomial.
